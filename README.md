# Flight Delay Analytics Dashboard

A simple end-to-end data analytics project that analyzes airline flight
delays, cancellations, and route performance using **Python, MySQL, SQL,
and Streamlit**.

Raw flight records are cleaned with Pandas, loaded into a single MySQL
table, queried with plain SQL, and visualized in an interactive Streamlit
dashboard.

## Objective

Turn raw flight records into business insights that help identify:

- Airlines with the highest delays
- Most delayed routes
- Cancellation patterns
- Airport performance
- Monthly delay trends

## Architecture

```
CSV Dataset
     │
     ▼
Python (Pandas) — Data Cleaning
     │
     ▼
MySQL Database (single flat table)
     │
     ▼
SQL Queries
     │
     ▼
Streamlit Dashboard
```

No foreign keys, no dimension/fact tables, no star schema, no warehouse —
intentionally kept simple.

## Dataset

A 30,000-row sample of historical U.S. airline on-time performance
records, trimmed to 8 columns:

| Column      | Description                              |
|-------------|-------------------------------------------|
| FL_DATE     | Flight date                               |
| AIRLINE     | Airline name                              |
| ORIGIN      | Origin airport code                       |
| DEST        | Destination airport code                  |
| DEP_DELAY   | Departure delay in minutes                |
| ARR_DELAY   | Arrival delay in minutes                  |
| CANCELLED   | 1 if cancelled, 0 otherwise                |
| DISTANCE    | Flight distance in miles                  |

The sample includes a small amount of intentionally messy data (duplicate
rows, missing values, and a few invalid outlier values) so the cleaning
script has real work to do — this is meant to make the pipeline genuinely
demonstrable rather than a no-op.

## Database Design

One flat table, no relationships:

```sql
CREATE TABLE flights (
    flight_date DATE,
    airline     VARCHAR(50),
    origin      VARCHAR(10),
    destination VARCHAR(10),
    dep_delay   FLOAT,
    arr_delay   FLOAT,
    cancelled   TINYINT,
    distance    FLOAT
);
```

## Setup & Run Instructions

### 1. Prerequisites

- Python 3.9+
- MySQL Server running locally (or update `scripts/db_config.py` to point
  elsewhere)

### 2. Install dependencies

From the project root:

```bash
pip install -r requirements.txt
```

### 3. Configure your database connection

Open `scripts/db_config.py` and confirm/edit these values to match your
MySQL setup:

```python
DB_HOST = "localhost"
DB_PORT = 3306
DB_USER = "root"
DB_PASSWORD = "your_password_here"
DB_NAME = "AirlineDW_Project"
```

This file already handles special characters (like `@`) in your password
via URL-encoding, so you don't need to escape anything manually.

You do **not** need to manually create the database — `load_mysql.py`
will create it for you if it doesn't exist. If you'd rather create it
yourself first, you can run `sql/create_table.sql` directly in MySQL
Workbench or the `mysql` CLI.

### 4. Clean the raw data

```bash
python scripts/clean_data.py
```

This reads `data/flights_small.csv`, removes duplicates, handles nulls,
fixes the date format, drops invalid delay/distance values, and writes
`data/flights_cleaned.csv`.

### 5. Load into MySQL

```bash
python scripts/load_mysql.py
```

This connects to MySQL, (re)creates the `flights` table, and bulk-inserts
the cleaned data.

### 6. (Optional) Run the SQL analysis from the command line

```bash
python scripts/analysis.py
```

Prints KPIs and all analytics query results directly to the terminal —
useful for sanity-checking before opening the dashboard.

### 7. Launch the dashboard

```bash
streamlit run dashboard/app.py
```

This opens the dashboard in your browser (usually at
`http://localhost:8501`).

## Troubleshooting

- **"Could not connect to MySQL"** — double check `scripts/db_config.py`
  credentials, and make sure your MySQL server is running
  (`mysql.server start` on macOS, or via Services on Windows).
- **"Access denied for user"** — your password in `db_config.py` doesn't
  match your actual MySQL root password.
- **Table is empty in dashboard** — make sure you ran `clean_data.py`
  *then* `load_mysql.py`, in that order, before launching the dashboard.
